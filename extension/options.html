Tabcat settings

How to group
Keep tabs organised

A moment after a tab loads, Tabcat moves it into the group it matches best. It won't put a tab back in a group you took it out of. Turn this off to group only when you press Tidy tabs.

Similar ungrouped tabs go into the new group with it. Turn this off to leave a tab alone until there's a group or another tab like it.

Tabcat's access to websites is turned off (about:addons → Tabcat → Permissions), so moves aren't shown on the page you're on. They're listed in Tabcat's popup instead.

Automatic grouping

Tabcat runs two small AI models on this computer: one to find related tabs, one to suggest names. The first run downloads them (about 80 MB) from Hugging Face; after that they're cached. Tab titles don't leave this computer, unless you name groups with an AI service elsewhere.

Higher keeps groups tighter and leaves more tabs alone. Lower groups more loosely.

Finding related tabs still happens on this computer; only naming the groups uses the service.

Model

Uses the model Tabcat already downloads for automatic grouping. Nothing to set up.

Also turn it on in about:config: set browser.ml.enable and extensions.ml.enabled to true. Firefox downloads the model the first time.

Where layad is listening (check with layad status). Only 127.0.0.1 addresses are allowed.

AI service

Any service with an OpenAI-compatible API: OpenAI, OpenRouter, or a model on this computer with Ollama or LM Studio. Tabcat sends it the titles, addresses and descriptions of the tabs it's grouping, unless the address is on this computer.

Up to and including /v1. For Ollama: http://localhost:11434/v1.

Not needed for Ollama or LM Studio. Kept in this Firefox profile and only sent to the address above.

Categories

Tabs the model is less sure about than this are left where they are.

The name becomes the group title. The model reads the description to decide what belongs, so describe the contents rather than just naming them.
